## 一、先决策：这个页面该怎么定位元素

**这是最重要的一步，选错方式会慢十倍。**

```
打开目标页面
   ↓
adb shell uiautomator dump 试一下，能读到目标文字吗？
   ├─ 能读到 → core/tools/tap.py "文字"      ← 约 1 秒，坐标 100% 准
   └─ 读不到 / 坐标明显不对 → 截图定位         ← 10-15 秒一步
        ├─ core/tools/see.sh -t "描述"        （小模型出坐标，省 token）
        └─ 或自己截图看（贵，但复杂页面更可靠）
```

**已知分类：**

| App / 页面 | 控件树 | 用什么 |
|---|---|---|
| 小红书（全屏原生） | ✅ 坐标准确 | `tap.py` |
| 微信（全屏原生） | ✅ 坐标准确 | `tap.py` |
| 系统对话框（权限弹窗等） | ✅ 坐标准确 | `tap.py` |
| **闲鱼首页 `MainActivity`** | ✅ **坐标准确**（2026-08-23 实点验证） | **`tap.py`** |
| 闲鱼频道内页 / 租房频道 `WebHybridActivity` | ❌ 读到 0 个文字 | 截图 |

**判断口径是 Activity，不是 App。** 同一个 App 里原生页能读、H5 页读不到是常态。

**遇到新 App，先花 30 秒做这个判断，别默认哪一种。**

## 二、硬规则

1. **一步一验证，绝不串联多步盲打**
   每次 tap 之后必须确认到了预期页面再走下一步：
   ```bash
   adb shell dumpsys window | grep mCurrentFocus   # 最快的验证方式
   ```
   2026-08-06 把「点我 → 点笔记 → 点设置 → 点编辑 → 点正文 → 清空」串成一条命令跑，某步没生效后面全部错位，最后点进了系统便签 App。

2. **用户随时会拿起平板自己用，「页面随时可能变」是前提不是异常**
   操作前先看当前在哪，别假设还停在上次的页面。

3. **绝不长期占用输入法**
   `hput.sh text` 已实现「记下原输入法 → 借用 ADBKeyboard → 输完立刻还回去」。
   手动切的话，**收工必须切回搜狗**：
   ```bash
   adb shell ime set com.sohu.inputmethod.sogou.xiaomi/.SogouIME
   ```
   用户打不了字 = 我的 bug。

4. **点击要有随机延迟和坐标抖动**（防风控），用 `hput.sh tap` 而不是裸 `input tap`

## 三、工具

| 工具 | 用途 | 什么时候用 |
|---|---|---|
| `core/tools/tap.py "文字"` | 读控件树，按文字点击 | **控件树可读的 App 首选** |

| `core/tools/hput.sh tap X Y` | 人类化点击（延迟 0.4-2.6s + ±12px 抖动） | 防风控场景 |
| `core/tools/hput.sh text "中文"` | 中文输入（自动借还输入法） | 输入中文 |

## 四、截图定位口径

```bash
adb exec-out screencap -p > s.png
sips -Z 1400 s.png --out screen.png     # 统一缩放到最长边 1400
# 实际坐标 = 图上坐标 × 2.2857   （= 3200/1400，横竖屏通用）
```

**裁剪放大看细节时，回算极易出错**（2026-08-06 在城市选择上栽过，点成了杭州）。能用完整图就别裁；必须裁时按实际 resize 倍数仔细回算。

## 五、中文输入

```bash
adb shell ime set com.android.adbkeyboard/.AdbIME
adb shell am broadcast -a ADB_INPUT_TEXT --es msg '文字'
# 带换行 / emoji / # 号的必须走 base64，否则丢字符
B64=$(base64 -i text.txt | tr -d '\n')
adb shell am broadcast -a ADB_INPUT_B64 --es msg "$B64"
```

- `--es msg` 里的 `#` **会被吃掉**，必须走 base64
- 输入前先 tap 输入框拿焦点

**清空文本域**（最麻烦的一环）：
- `ADB_CLEAR_TEXT` 广播：不生效
- `input keycombination 113 29`（Ctrl+A）：不生效，反而删掉一个字符
- 长按弹「全选」菜单：时灵时不灵，失败时新文本会追加到旧文本后面（出现过 1828/1000 字超限）
- ✅ 可靠办法：
  ```bash
  adb shell input keycombination 113 123            # Ctrl+End 跳文档末尾
  KEYS=$(python3 -c "print(' '.join(['67']*150))")  # 一条命令发 150 个删除键
  for i in $(seq 1 8); do adb shell "input keyevent $KEYS"; done
  ```
- ⚠️ **闲鱼的输入框 Ctrl+End 不跳末尾**，后面的内容要用 `FORWARD_DEL`（keycode 112）往后删

## 六、基础操作

```bash
adb devices
adb shell dumpsys trust | grep deviceLocked      # 1=锁屏 0=已解锁
adb shell dumpsys window | grep mCurrentFocus    # 当前 App/Activity

# 解锁
adb shell input keyevent KEYCODE_WAKEUP
adb shell input swipe 1600 1900 1600 600 200
adb shell input text "$LOCK_PIN"
adb shell input keyevent KEYCODE_ENTER
# ⚠️ 不要按 keyevent 26（电源键），那是关屏

# 推素材（推完必须逐个触发扫描，否则相册看不到）
adb push <目录>/. /sdcard/Pictures/xxx/
adb shell "am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///sdcard/Pictures/xxx/a.jpg"

# 收工
adb shell ime set com.sohu.inputmethod.sogou.xiaomi/.SogouIME
adb kill-server        # 之后别再跑 adb 命令，任何 adb 命令都会重新拉起 daemon
```

## 七、分层架构与模型

分层是为了省钱：Claude 决定"下一步做什么"（低频），小模型看屏出坐标（高频）。

```
Claude（大脑，低频）      决定下一步、处理异常、判断任务完成
    ↓ 子目标：「点开第一个商品」
qwen3-vl-plus（眼，高频）  看截图 → 出坐标    ~1150 token/次
    ↓ 坐标
hput.sh（手）             随机延迟+坐标抖动执行  防风控
    ↓ 截图回传，循环
```

- 百炼 key：`~/.config/secrets/dashscope.env` 的 `DASHSCOPE_API_KEY`
- **可用模型**：`gui-plus`（GUI 专用，见下）、`qwen3-vl-plus`、`qwen-vl-max`、`qwen-vl-plus`、`qwen3-vl-30b-a3b-instruct`
- **不可用**：`qwen2.5-vl-*`（需单独申请）、`qwen-vl-max-latest`（此 key 无权限，2026-08-06 实测）
- 查当前 key 有哪些模型：`GET https://dashscope.aliyuncs.com/compatible-mode/v1/models`（本 key 共 241 个）

### GUI-Plus：界面交互专用模型（2026-08-23 发现）

> 推翻旧结论：~~"gui-owl-* 百炼没有"~~ ——百炼有**同类**的 `gui-plus`，本 key 直接可调，无需申请。

- 模型名：`gui-plus` / `gui-plus-2026-02-26`（后者支持 `enable_thinking`）
- **必须给 `mobile_use` 工具定义的 system prompt，否则退化成普通 VL 模型只会写作文**（2026-08-23 实测：不给工具定义时，问它"点击某某"，它返回一段解释性文字，不给坐标）
- 输出格式：`Action: 描述` + `<tool_call>{"name":"mobile_use","arguments":{"action":"click","coordinate":[x,y]}}</tool_call>`
- 🔴 **两个版本坐标系不同，官方文档没写这件事**（2026-08-23 对照实测，同图同目标）：

  | 模型 | 返回坐标系 | 用法 |
  |---|---|---|
  | `gui-plus` | **真实像素** | 直接用，**不要再换算** |
  | `gui-plus-2026-02-26` | 0-1000 归一化 | `x/1000*真机宽` |

  照文档对 `gui-plus` 做归一化换算 → 坐标飞出屏幕数倍，全部判错。
- prompt 里的分辨率**按文档写 `1000x1000` 即可**；写真实分辨率反而略差（实测 (1482,3078) vs (1508,3075)，真值 (1515,3097)）。模型不依赖这个声明。
- 手机端动作空间：`key / click / long_press / swipe / type / system_button / open / wait / answer / interact / terminate`
- 高分辨率：`vl_high_resolution_images: true`（像素上限提到 12,845,056）
- 文档：https://help.aliyun.com/zh/model-studio/gui-automation
- **Qwen3-VL 返回 0-1000 千分比归一化坐标**，不是像素！换算必须 `x/1000*真机宽`
- **国内 API 不能走代理**：python 里 `build_opener(ProxyHandler({}))`，curl 加 `--noproxy '*'`

成本：Claude 直接看原图 ~2500 token/帧；qwen3-vl-plus 看缩略图 ~1150 token/帧且单价便宜十倍。

## 八、设备与环境

- 小米平板 24091RPADC（Xiaomi Pad 7 Pro），HyperOS，Android 16，**2136×3200**
- adb 序列号 `<设备序列号>`，锁屏密码见本地配置
- adb 路径：`~/Library/Android/platform-tools/adb`（软链到 `/opt/homebrew/bin`，腾讯云镜像装的，**dl.google.com 直连超时**）
- 已装输入法：搜狗（默认）、百度、讯飞、**ADBKeyboard**

**设备相关的坑**：
- MIUI/HyperOS 要开「USB调试(安全设置)」才允许模拟点击
- `wm size` 伪装 1080x2400 在 HyperOS 上黑屏，放弃；原生分辨率识别无障碍
- HyperOS 会随机冻结后台服务，关电池优化、省电设为无限制、最近任务上锁能缓解
- 登录页 / 支付页有 `FLAG_SECURE`，截图全黑，只能用户手动
- 动画会让截图糊，把三个 animation scale 关掉

## 九、能力边界（实测结论）

**适合**：多平台批量发布、一处改动同步刷多个地方、需要精确计算的信息整理、无人值守时段作业。
2026-08-06 租房任务：凌晨从零发完两个平台；文案改四轮全平台同步（人手工做一小时以上且容易漏改）。

**不适合**：即时私信对话。回一条私信要 5-6 次 adb 调用 + 3 次验证，约 1-2 分钟；人十几秒。**聊天让人做。**

**行业参照**：商用手机助手做通用任务成功率约 20%（21世纪经济报道+复旦，2026-02），但**固定的、调优过的窄任务能到 90%+**。
路径是：先把一件事调到能用，再加第二件，不追求开箱即用什么都行。
